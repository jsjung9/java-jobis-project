# ADR 0001: 리프레시 토큰 회전과 HttpOnly 쿠키

- 상태: 적용
- 날짜: 2026-09-10

## 배경

액세스 토큰은 브라우저 JavaScript에서 API 헤더에 사용하지만 수명을 짧게 유지해야 한다. 장기 리프레시 토큰까지 같은 저장소에 두면 스크립트 취약점이 세션 전체를 탈취할 수 있고, 갱신 뒤에도 기존 토큰이 계속 유효하면 재사용을 구분하기 어렵다.

## 결정

리프레시 토큰은 HttpOnly, SameSite 쿠키로 전달하고 서버 Redis에도 사용자 ID별 현재 토큰을 저장한다. `/user/token`은 쿠키와 Redis 값의 일치를 확인한 뒤 새 액세스·리프레시 토큰을 발급하고 Redis 값을 즉시 교체한다. 로그아웃은 Redis 값과 쿠키를 모두 제거한다.

## 결과

JavaScript는 리프레시 토큰에 접근하지 않는다. 탈취된 이전 리프레시 토큰은 한 번 정상 갱신된 뒤 서버 값과 달라져 거부된다. HTTPS 운영에서는 `JWT_COOKIE_SECURE=true`가 필수다. 액세스 토큰은 현재 UI 구조상 localStorage에 있으므로 CSP와 출력 인코딩 같은 XSS 방어가 여전히 중요하다.
