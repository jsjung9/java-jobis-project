# ADR 0002: 뉴스 수집·분석 서비스 분리

- 상태: 적용
- 날짜: 2026-09-10

## 배경

기업·사용자 API는 DB 중심의 짧은 요청이지만 뉴스 기능은 검색 API, 기사 페이지, LLM이라는 세 외부 시스템에 의존한다. Python의 텍스트 처리 생태계를 활용하면서도 외부 지연이 핵심 API의 도메인 코드로 퍼지지 않게 해야 했다.

## 결정

Spring API는 기업 ID 캐시와 사용자에게 보이는 오류 계약을 담당한다. FastAPI는 기업명 검증, Naver 수집, 허용 호스트 확인, 기사 정규화, OpenAI 구조화 분석을 담당한다. 서비스 간 응답을 Pydantic과 Java DTO 양쪽에서 명시하고, Spring 호출은 5초 안에 끝낸다.

## 결과

외부 기능을 독립 테스트·교체할 수 있고 캐시 hit에서는 Python과 외부 API를 거치지 않는다. 반면 서비스가 하나 늘어 배포와 관찰 지점도 늘었다. 현재는 한 프로세스 안의 thread pool에서 동기 SDK를 실행하므로, 처리량이 늘면 작업 큐와 비동기 결과 조회를 검토한다.
