# 요구사항과 완료 기준

## 제품 목표

구직자가 인지도가 낮은 기업도 객관적인 지표로 탐색하고 비교할 수 있어야 한다. 한 기업의 재무·고용·복지·특허·뉴스 정보를 여러 사이트에서 반복 검색하는 비용을 줄이고, 사용자의 선호를 다음 후보 탐색에 반영한다.

## 기능 요구사항

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| COM-01 | 기업 검색 | 이름 일부, 복수 지역, 복수 유형을 함께 적용하고 페이지 결과와 전체 건수를 반환한다. |
| COM-02 | 기업 상세 | 존재하는 기업의 기본·재무·분기·복지·특허 정보를 항목별로 조회한다. 없는 ID는 404로 응답한다. |
| COM-03 | 인기 기업 | 조회수 상위 10개 기업을 내림차순으로 반환한다. 상세 조회의 증가 연산은 동시 요청에도 값을 잃지 않는다. |
| USR-01 | 회원 가입·로그인 | 이메일 형식을 검증하고 소문자로 정규화하며 비밀번호 원문을 저장하지 않는다. |
| USR-02 | 세션 유지 | 짧은 수명의 액세스 토큰과 HttpOnly 리프레시 토큰을 사용한다. 갱신할 때 리프레시 토큰을 회전한다. |
| USR-03 | 관심 기업 | 로그인한 사용자는 같은 기업을 중복 저장하지 않고 자신의 저장 내역만 조회·삭제한다. |
| USR-04 | 기업 성향 | 다섯 성향 점수를 유효 범위 안에서 저장하고 자신의 결과만 조회한다. |
| REC-01 | 선택 토너먼트 | 한 요청에서 중복되지 않는 후보 16개를 제공한다. 후보가 부족하면 정상 결과처럼 축소하지 않는다. |
| REC-02 | 기업 추천 | 선택 결과와 관계가 설정된 기업을 중복 없이 반환한다. |
| NEWS-01 | 뉴스 수집 | 기업명 길이와 문자를 검증하고 신뢰하는 네이버 기사 주소에서만 본문을 가져온다. |
| NEWS-02 | 뉴스 분석 | 최대 건수와 시간 제한 안에서 뉴스 키워드, 중요도 0~10, 긍·부정 값을 구조화해 반환한다. |
| NEWS-03 | 캐시 | 기업 ID별 분석 결과를 Redis에 저장해 반복 외부 호출을 줄인다. |
| PAT-01 | 특허 결합 | 특허 원천 파일과 기업 기준 CSV를 명시적 인자로 받고, 유효한 사업자번호가 일치하는 특허만 출력한다. |

## 비기능 요구사항

- 비밀값은 Git 추적 파일이 아니라 환경 변수로 주입한다.
- 공개 조회 API와 로그인 사용자 API를 서버 보안 설정에서 구분한다.
- API 오류는 HTTP 상태, 코드, 메시지가 있는 JSON 계약으로 반환한다.
- 외부 HTTP 요청에는 연결·응답·전체 처리 시간 상한을 둔다.
- 서버는 한 번에 최대 100개 기업만 반환한다.
- 데이터베이스 연결을 응답 렌더링까지 유지하지 않는다(`open-in-view=false`).
- 운영 프로필은 스키마를 자동 변경하지 않고 `validate`로 불일치를 드러낸다.
- 네 모듈의 빌드·테스트·정적 분석을 Pull Request와 push마다 독립 실행한다.

## 범위와 한계

이 저장소는 포트폴리오용 복구·현대화 프로젝트다. 원 데이터의 최신성, Naver 검색 결과의 장기 보존 권한, 실제 OAuth 공급자 설정은 배포 운영자가 별도로 확인해야 한다. 외부 뉴스와 OpenAI 통합은 자동 테스트에서 모의하며, 실제 키를 사용한 종단 간 호출은 로컬 검증 범위에 포함하지 않는다.
